# ADR-002 — Safari 화면 확장과 PoC 게이트

날짜: 2026-10-27. 상태: 실험 전략 채택, 제품 확장 방식 미채택.

문제: 문서 폭을 키우는 것과 Safari의 시스템 UI 뒤로 그리는 것은 다르다.
선택: A~F를 분리한 수동 PoC. root 폭 증가, CSS overflow, 배경/이미지 변경,
viewport-fit 변경을 각각 측정하고 원래 상태로 복구한다. 사용자 페이지 자동 변경은 하지 않는다.
`screen.width - innerWidth`를 곧바로 확장 가능 폭으로 사용하지 않는다.
VisualViewport는 키보드/확대에서도 달라지므로 zoom 상태를 접힘으로 해석하지 않는다.

대안: 고정 250px 확장, 기기 UA 감지, CSS transform로 축소, 무조건 cover 삽입.
이들은 좌표·확대·안전 영역·호환성을 보장하지 못하므로 제품 전략으로 채택하지 않는다.
근거: WebKit 27.1 공식 글은 기본적으로 시스템 조작 영역 뒤에 웹 콘텐츠가 들어가지 않으며,
향후 해법을 검토 중이라고 설명한다. CSS 우회 가능성은 실제 실험 없이는 확정할 수 없다.
접힘/세그먼트 API는 기능 플래그 뒤의 프리뷰이므로 제품 필수 의존성으로 삼지 않는다.

성공 조건: Safari UI 뒤 실제 이미지/배경 픽셀 증가가 스크린샷으로 확인되고,
가로 흔들림·텍스트/버튼 가림·탭 불가가 없으며 OFF로 viewport/스타일/리스너를 복구한다.
실기기에서 외부 화면 양 방향, 내부 화면, 확대, 스크롤, 회전을 각각 검사한다.
실패/환경 부족이면 제품 Smart/Full Width를 완료라고 표시하지 않는다.
검증 갱신(2026-10-28): iOS 27.1 Duo 시뮬레이터 외부 화면 세로 fixture에서
문서 폭/CSS 폭/표식 배경의 시스템 영역 뒤 렌더링과 OFF 복구 PASS.
cover 단독은 확장되지 않았고, 전체 문서 폭 실험은 본문 가림이 확인됐다.
clip 후에도 프로그램 수평 스크롤이 가능하므로 스크롤 잠금/터치 안전성을 보장하지 못한다.
후속 후보 `scroll-lock`은 배율 1에서만 가로 원점을 유지하며, 실제 Duo의 프로그램 이동을 x=0으로 억제했다.
확대 중 가로 이동을 허용하고 OFF에서 리스너와 기존 x 위치를 복구한다. Duo 시뮬레이터의 네이티브 드래그/핀치/확대 중 재적용/OFF 통합 검사를 통과했다.
본문 가림 해결 후보는 body 원래 폭/여백 고정 + 표식 배경 확장이다.
기존 폭 증가·스크롤 잠금·조건부 복구를 재사용하고 임의 사이트 탐지는 추가하지 않는다.
대안인 전체 문서 확장은 본문 가림 때문에 제품 기본값으로 채택하지 않는다.
예상 위험은 body 폭 고정에 따른 반응형/SPA 호환성으로, 회전·노드 교체 검증 전 제품 모드로 승격하지 않는다.
팝업 주입/측정 응답은 실제 XCTest로 확인했다. 전체 제품 안전 게이트는 아직 통과하지 않았다.
개별 A~F와 실제 자동 검사 결과: [VIEWPORT.md](../technical/VIEWPORT.md).

자료: [Safari 27.1](https://webkit.org/blog/18486/webkit-features-for-safari-27-1/),
[Safe Area](https://webkit.org/blog/7929/designing-websites-for-iphone-x/).

후속 Full Width: 배경 확장만으로는 사용자가 원하는 본문 재배치를 제공하지 못해 별도 full-width 모드를 추가한다.
body까지 넓히며 OFF에서 조건부 복구한다. 보호 배경은 기본값으로 유지하고 선택 모드만 로컬에 저장한다.
콘텐츠/버튼의 Safari 조작부 겹침 위험을 명시하며 이 모드를 안전한 보호 배경으로 주장하지 않는다.
실제 aeogae.com 본문 폭 증가와 레이아웃 변화는 artifacts/aeogae/full-visible.xcresult 및 캡처로 확인했다.
