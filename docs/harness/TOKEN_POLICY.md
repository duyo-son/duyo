# 토큰과 비용 정책

- 세션 시작은 CLAUDE.md → STATE.md → 관련 소스 → 해당 ADR/기술 문서 순서다.
- `rg --files`와 범위를 좁힌 `rg -n`을 먼저 사용한다. 전체 저장소를 반복 출력하지 않는다.
- 긴 파일은 필요한 함수와 호출부만 읽고, 공식 근거는 기술 문서에 날짜/URL로 보존한다.
- 규칙은 paths 조건부, 3개 절차 Skill은 수동 실행이다. 전체 문서를 @import하지 않는다.
- 독립된 대량 조사의 문맥 격리만 위임하고, 동시에 2개 이하다. 1~2개 파일 작업은 메인이 처리한다.
- 모델은 [MODEL_ROUTING.md](MODEL_ROUTING.md). 빈번한 변경에 따른 문맥 재구성 비용도 고려한다.
- 테스트 실행과 결과 집계는 모델 없이 스크립트로 처리한다. 정상 로그를 재분석하거나 성공한 전체 검사를 반복하지 않는다.
- 단순 사실 조사는 호출 검증된 Haiku, 구현·복잡한 실패 분석은 Sonnet을 사용한다.
- 정상 테스트 로그는 요약하고 실패 원인과 관련 부분만 표시한다.
- 응답은 완료/변경/검증/다음, STATE는 최신 상태만 유지하며 작업 일지를 쌓지 않는다.

측정은 설치된 Ponytail의 `/ponytail band`를 우선한다. 입력/출력 토큰, 캐시 사용량,
작업 비용/시간/테스트가 실제 제공될 때만 활용한다. 프로젝트 자체 비용 추정기를 만들지 않는다.
Ponytail 외부 webhook은 프로젝트에서 설정하지 않는다. 개발자 개인 설정의 외부 통신 정책은 별도 확인한다.
API 실패의 0 사용량을 정상 작업 비용이나 토큰 절감량으로 주장하지 않는다.
미제공 수치는 `미제공`, 실행하지 않은 측정은 `미실행`으로 표시한다.
이번 Codex 작업의 총비용/캐시 비율은 미제공이다.
